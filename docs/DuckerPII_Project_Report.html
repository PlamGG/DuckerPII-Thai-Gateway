1. บทนำและความสำคัญของโปรเจกต์ (Executive Summary)

ในยุคที่องค์กรเร่งนำเทคโนโลยี Large Language Models (LLMs) และ Generative AI เข้ามาประยุกต์ใช้ในระบบบริการลูกค้า เช่น แชตบอตตอบคำถามอัตโนมัติ และระบบสรุปข้อมูลธุรกรรม ปัญหาสำคัญที่สุดคือ ความเสี่ยงต่อการรั่วไหลของข้อมูลระบุตัวบุคคล (Personally Identifiable Information: PII) เข้าสู่เซิร์ฟเวอร์ภายนอก ซึ่งขัดต่อ พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) และแนวปฏิบัติ AI ฉบับ 1.0 ของสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส. / PDPC)

DuckerPII ถูกพัฒนาขึ้นเพื่อทำหน้าที่เป็น "Privacy Reverse Proxy Gateway" ที่มีความเร็วสูงระดับมิลลิวินาที คั่นอยู่ตรงกลางระหว่างผู้ใช้งานกับโมเดลภาษาขนาดใหญ่ โดยคัดกรอง เซ็นเซอร์ และแปลงข้อมูล PII ทั้ง 7 หมวดหมู่หลักให้อยู่ในรูปนิรนาม (Anonymized Tokens) ก่อนส่งต่อ ทำให้องค์กรสามารถใช้งาน Cloud AI ได้อย่างมั่นใจและถูกกฎหมาย 100%

2. สถาปัตยกรรมชุดข้อมูลสังเคราะห์ (Synthetic Dataset Engine v6.0.0)

เพื่อตัดปัญหาความเสี่ยงทางกฎหมายตั้งแต่ต้นทาง ข้อมูลทั้งหมด 20,000 ประโยค (60,677 Entities) ถูกสร้างขึ้นผ่านอัลกอริทึมสังเคราะห์ 100% (Zero Real-World PII) ตามแนวทาง Privacy Enhancing Technologies (PETs) โดยแบ่งออกเป็น 4 เสาหลักทางวิศวกรรมข้อมูลเพื่อแก้ปัญหา Shortcut Learning (การจำคำนำหน้าตายตัว):

  • 50% Trigger Word Dropout: สุ่มตัดคำนำหน้า เช่น "ชื่อ:", "เบอร์โทร:", "ที่อยู่:" ออก เพื่อบังคับให้โมเดลเรียนรู้จากบริบทแท้จริงของคำ
  • 30% Hard Numeric Negatives: ฝังตัวเลขรหัสพัสดุ (Flash/Kerry), เลขคำสั่งซื้อ (#ORD-), บาร์โค้ดสินค้า และป้ายราคาเป็น Negative Label (O) เพื่อแก้ปัญหาโมเดลจำตัวเลขทุกชุดเป็นเบอร์โทรหรือเลขบัญชี
  • Fragmented Urban Addresses: จำลองที่อยู่สั้นแบบคนเมือง เช่น ชื่อคอนโด อาคารสำนักงาน หรือแลนด์มาร์กข้างทางที่ไม่มีตำบล/อำเภอ/รหัสไปรษณีย์ครบถ้วน
  • Adversarial Noise & Slang: รองรับคำสะกดผิด สแลงแชต (เช่น "เบอ", "บช", "ที่ยุ") และการเว้นวรรคแบบไม่สม่ำเสมอ

3. สถาปัตยกรรมระบบไฮบริด (Two-Tier Hybrid Architecture)

จุดเด่นสำคัญของ DuckerPII คือการไม่พึ่งพาโมเดล AI เพียงอย่างเดียว แต่ใช้สถาปัตยกรรมแบบสองชั้น (Cascaded Hybrid) เพื่อการันตีความถูกต้องระดับ Zero-Trust: 

[ข้อความแชตจากลูกค้า (Unstructured Text)]
                 │
                 ▼
 ┌────────────────────────────────────────────────────────┐
 │ Tier 1: โมเดล Transformer Neural NER                   │
 │ (DuckerPII-Thai-Base: RoBERTa Contextual Tagging)      │
 └───────────────────────┬────────────────────────────────┘
                         │ Candidate Spans (ช่วงคำที่ตรวจพบ)
                         ▼
 ┌────────────────────────────────────────────────────────┐
 │ Tier 2: Deterministic Post-Processing Safety Gate      │
 │  ├── ตรวจสอบเลขบัตรประชาชนด้วยสูตร Mod11 Checksum       │
 │  ├── ตรวจสอบเบอร์โทรด้วย Regex Prefix (06, 08, 09, +66)│
 │  ├── ตรวจสอบอีเมลด้วย RFC Fullmatch Validation          │
 │  └── คัดกรองตัวเลขธุรกิจ/บาร์โค้ด ออกจากชื่อบุคคล       │
 └───────────────────────┬────────────────────────────────┘
                         │ Sanitized Entities (ปลอดภัย 100%)
                         ▼
 ┌────────────────────────────────────────────────────────┐
 │ โหมดการแปลงข้อมูล (Three Production Output Modes)       │
 │  1. Placeholder Masking: ส่งต่อไปยัง External LLM       │
 │  2. Synthetic Anonymization: สลับเป็นข้อมูลสังเคราะห์   │
 │  3. Reversible Audit Vault: JSON กู้คืนข้อความต้นฉบับ   │
 └────────────────────────────────────────────────────────┘

6. ตัวอย่างการนำไปใช้งานจริง (Production Quickstart)

นักพัฒนาและทีมวิศวกรรมข้อมูลสามารถดึงโมเดลไปใช้งานในระบบ Pipeline ได้ทันทีผ่านไลบรารี transformers: 

from transformers import pipeline

# 1. โหลดโมเดล DuckerPII ผ่าน Hugging Face Hub
ner_pipeline = pipeline(
    "token-classification",
    model="DuckerMaster/DuckerPII-Thai-Base",
    aggregation_strategy="simple"
)

# 2. ป้อนข้อความแชตจากลูกค้า
raw_chat = "คุณกานดา จันทร์เพ็ญ โอนเงิน 500 บาท เข้าบัญชี 098-7-65432-1 ธนาคารกรุงไทย นะคะ"
results = ner_pipeline(raw_chat)

# 3. เซ็นเซอร์ข้อมูล PII ก่อนส่งเข้า Cloud LLM
masked_text = raw_chat
for entity in sorted(results, key=lambda x: x["start"], reverse=True):
    masked_text = (
        masked_text[:entity["start"]]
        + f"<{entity['entity_group']}>"
        + masked_text[entity["end"]:]
    )

print("ข้อความต้นฉบับ :", raw_chat)
print("ข้อความที่เซ็นเซอร์ :", masked_text)
# ผลลัพธ์: <NAME> โอนเงิน 500 บาท เข้าบัญชี <BANK_ACC> <BANK> นะคะ

7. ความสอดคล้องทางกฎหมายและความปลอดภัย (Legal & Ethics)

ข้อกำหนดการใช้งานและการคุ้มครองข้อมูลส่วนบุคคล (PDPA Compliance)
  • สถานะทางกฎหมาย: เนื่องจากข้อมูลที่ใช้ฝึกฝนเป็นข้อมูลสังเคราะห์ 100% (Synthetic Data) ที่สร้างจากอัลกอริทึม จึงได้รับการยกเว้นจากการอยู่ภายใต้บังคับของ พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 ตามคำประกาศของ สคส. (PDPC) และจัดเป็นเทคโนโลยีเพื่อการคุ้มครองความเป็นส่วนตัว (PETs)
  • ข้อห้ามการใช้งาน: ห้ามนำตัวเลขจำลอง (เช่น เลขบัตรประชาชนที่ผ่าน Mod11 Checksum หรือเบอร์โทรศัพท์จำลอง) ไปใช้ในการโทรติดต่อจริง การทำธุรกรรมทางการเงิน หรือการหลอกลวงใดๆ โดยเด็ดขาด
